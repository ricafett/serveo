# Deployment

This document describes how to deploy and operate the Serveo MVP. The
application is a modular Laravel monolith (PHP 8.3+, Laravel 11, Filament 3,
Livewire 3) with a PostgreSQL database, Redis-backed queues for printing,
and a backend-owned print subsystem with pluggable adapters for LAN
ESC/POS printers and a USB print agent.

## 1. Stack overview

| Component   | Purpose                                             |
| ----------- | --------------------------------------------------- |
| `app`       | PHP-FPM (Laravel) - Filament admin and Livewire UI |
| `web`       | nginx 1.27 reverse proxy serving the app on `:8080` |
| `postgres`  | PostgreSQL 16 — primary data store                  |
| `redis`     | Redis 7 — queue backend (`prints` queue + default)  |
| `worker`    | `php artisan queue:work redis` (prints,default)     |
| `scheduler` | Loops `php artisan schedule:run` every 60 seconds; waits for `app` bootstrap |

The kitchen and bar are non-interactive in MVP: they only receive printed
production tickets. Customer bills are printed only on cashier-assigned
printers. Failed print jobs persist in the database and remain retryable
through Filament *Operação → Trabalhos de impressão* and the
`PrintQueueService::retry()` API.

## 2. Prerequisites

Host machine for the service:

- Linux (tested with Ubuntu 22.04+, Debian 12) or macOS
- Docker Engine 24+ and Docker Compose plugin
- Outbound network access for Composer/Node mirror resolution at build time
- For LAN printers: same L2/L3 network as the printers, port 9100 reachable
- For USB printers: a separate Print Agent (see §6.2) running on the host
  the printer is plugged into

For local development without Docker:

- PHP 8.3 with extensions: `pdo_pgsql`, `mbstring`, `intl`, `bcmath`,
  `redis`, `gd`, `zip`, `xml`
- Composer 2.6+
- PostgreSQL 16
- Redis 7

## 3. Quick start with Docker Compose

```bash
git clone https://github.com/ricafett/serveo.git
cd serveo

# 1. Environment file
cp .env.example .env
# Edit .env if needed; the defaults match the docker-compose services.

# 2. Build images and start the stack
docker compose build
docker compose up -d postgres redis
docker compose up -d app web worker scheduler

# 3. Install dependencies & generate app key
docker compose exec app composer install --no-dev --optimize-autoloader
docker compose exec app php artisan key:generate
docker compose exec app php artisan storage:link

# 4. Wait for app bootstrap (migrations, seed, optimize) to complete
docker compose ps

# 5. Visit the admin
open http://localhost:8080/admin/login
```

Default seeded users (all with password `password`):

| Username  | Role    | Notes                           |
| --------- | ------- | ------------------------------- |
| admin     | ADMIN   | Full access                     |
| cashier1  | CASHIER | Caixa screen + payment recording |
| server1   | SERVER  | Floor + order entry              |

> **Important:** rotate every default password before any production use.

`prints` queue.

## 4.1 PHP-FPM and Opcache runtime tuning

The production app image ships with an explicit PHP-FPM pool override and
production-oriented Opcache settings.

### PHP-FPM pool

The `app` container runs PHP-FPM with:

```ini
pm = dynamic
pm.max_children = 24
pm.start_servers = 8
pm.min_spare_servers = 8
pm.max_spare_servers = 16
pm.max_requests = 1000
```

These values are sized for a dedicated host with moderate concurrent operator
load and are intended to avoid the stock Docker image defaults becoming the
bottleneck under Livewire request bursts.

### Opcache

Production uses:

```ini
opcache.memory_consumption=256
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=20000
opcache.validate_timestamps=0
opcache.revalidate_freq=0
opcache.enable_file_override=1
zend.assertions=-1
realpath_cache_size=16384K
realpath_cache_ttl=600
```

`opcache.validate_timestamps=0` means code changes are **not** detected
automatically after the container starts. In production, new code requires a
container rebuild/redeploy or restart.

### Development override

`docker-compose.dev.yml` mounts a dev-only ini override for the PHP containers
that restores:

```ini
opcache.validate_timestamps=1
opcache.revalidate_freq=0
```

This keeps local source-code edits visible without rebuilding the image while
preserving the production runtime defaults in the base image.

## 5. Migrations, seeding, and assets

```bash
# Migrations only (no seed) on a managed Postgres
docker compose exec app php artisan migrate --force --isolated

# Optimise framework caches for production
docker compose exec app php artisan config:cache
docker compose exec app php artisan route:cache
docker compose exec app php artisan view:cache
docker compose exec app php artisan icons:cache
docker compose exec app php artisan filament:cache-components

# Front-end assets
docker compose exec app npm ci
docker compose exec app npm run build
```

If you ever need to wipe and reseed (development only):

```bash
docker compose exec app php artisan migrate:fresh --seed
```

## 6. Printing setup

The print subsystem is backend-owned. Browser printing is **never** the
source of truth: every ticket and bill is queued as a `print_jobs` row,
dispatched by the `serveo-worker` container, and remains retryable until it
reaches `PRINTED`.

### 6.1 LAN printers (preferred)

1. Configure each printer with a static IP on the venue VLAN.
2. In the admin, navigate to *Configuração → Impressoras* and create a
   record per printer with:
   - **Tipo de ligação:** `LAN`
   - **Endereço:** the IP address
   - **Porta:** `9100` (default)
3. Under *Configuração → Rotas de impressão*, route document types to
   printers (`PRODUCTION_TICKET / KITCHEN`, `PRODUCTION_TICKET / BAR`,
   `BILL / CASHIER`, `VOID_SLIP / KITCHEN`, ...).
4. Assign each cashier user to a `BILL` printer in
   *Configuração → Atribuições de impressora de caixa*. Bills will only
   ever route to a cashier printer.

The bundled `LanEscPosAdapter` opens a TCP connection per job, sends an
ESC/POS payload (init `ESC @`, body, full cut `GS V 1`) and reports a
machine-readable error message on failure. Failures populate
`printers.last_error`/`health_status` and leave the `PrintJob` in `FAILED`
for cashier retry.

### 6.2 USB printers (via Print Agent)

When a printer is reachable only from a Windows/macOS host, set
**Tipo de ligação** to `USB_AGENT` and provide:

- **Agent endpoint:** `https://print-agent.local:7000/print`
- **Agent printer ID:** the local printer name registered on the agent

The `UsbAgentAdapter` makes an HTTP `POST` to that endpoint with the
ESC/POS payload as the request body and the `X-Printer-Id` header. Any
non-2xx response (or timeout) marks the job `FAILED`. The Print Agent
itself is a separate, small daemon the venue installs on the host; no
browser is in the loop.

A reference null adapter (`connection_type=NULL`) is provided for
development: it writes payloads to `storage/app/print-jobs/`. This is
convenient for QA and is what the test suite exercises.

### 6.3 Operating the print queue

- *Operação → Trabalhos de impressão* lists every job with status, attempts,
  last error and target printer.
- A failed job has a **Retry** action; cancelled jobs can also be re-queued.
- `php artisan queue:work redis --queue=prints` is what the `worker`
  container runs. Scale by adding more replicas of that service.

## 7. Backups and disk

- **Postgres**: snapshot the `serveo_pgdata` volume daily and retain at least
  7 days. Use `pg_dump -Fc` for off-site copies.
- **Config backups**: include admin/config reference data only. They must not
  include the `migrations` table; restore validation should reject any config
  backup that contains migration bookkeeping or operational tables.
- **Redis**: durable AOF is enabled; the `serveo_redisdata` volume contains
  ephemeral queue state — losing it loses pending print jobs only (which
  cashiers can re-trigger from the UI).
- **Printer payloads (NullAdapter only)**: `storage/app/print-jobs/` is
  considered debug output and can be rotated/discarded.

## 8. Operational runbook

```bash
# Tail application logs
docker compose logs -f app worker

# Restart only the worker (e.g. after PHP code change)
docker compose restart worker

# Tinker into the running container
docker compose exec app php artisan tinker

# Run the test suite
docker compose exec app ./vendor/bin/pest

# Run migrations on a hot deploy
docker compose exec app php artisan migrate --force --isolated \
  && docker compose restart app \
  && docker compose restart worker scheduler
```

### Common incidents

| Symptom                                  | Action                                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------- |
| Tickets not printing in kitchen          | Check *Trabalhos de impressão*; retry; verify the LAN printer is reachable on :9100. |
| Cashier sees "No cashier printer assigned" | Add a row in *Atribuições de impressora de caixa* for that user.                    |
| Group cannot be opened in a row          | Likely an `OccupiedZone` overlap — release the conflicting zone in the group detail.  |
| Worker container stuck                   | `docker compose restart worker`; jobs older than `next_attempt_at` are picked up.    |

## 9. Upgrading

```bash
git pull

docker compose exec app composer install --no-dev --optimize-autoloader
docker compose exec app php artisan migrate --force --isolated
docker compose exec app php artisan config:cache view:cache route:cache
docker compose restart app
docker compose restart worker scheduler
```

## 10. Production hardening checklist

- [ ] Change all seeded passwords; remove unused seed users.
- [ ] Set `APP_DEBUG=false`, generate fresh `APP_KEY`.
- [ ] Verify the dedicated host memory budget still supports the baked-in
      PHP-FPM pool (`pm.max_children = 24`) after any major dependency or
      workload change.
- [ ] Redeploy or restart the `app` container after every production code
      change; Opcache timestamp validation is disabled by design.
- [ ] Put nginx behind TLS (e.g. Caddy or an upstream LB with Let's Encrypt).
- [ ] Restrict the Postgres and Redis ports to the internal network
      (`expose:` instead of `ports:` once the app no longer needs host access).
- [ ] Configure log rotation for `storage/logs/laravel.log`.
- [ ] Add nightly `pg_dump` to off-host storage.
- [ ] Smoke-test print routing (KITCHEN, BAR, BILL, VOID_SLIP) on day-zero.
